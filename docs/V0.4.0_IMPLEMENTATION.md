# v0.4.0 Implementation Summary

## Objective

v0.4.0 introduces an orbit-context layer that can explain measured/replayed LEO communication events with reproducible visible-satellite candidate information.

## Implemented

### Orbit input and provenance

- OMM JSON loader
- OMM CSV loader
- legacy TLE loader
- automatic format detection
- satellite selection by name, catalog ID, or object ID
- SHA-256 source manifest
- source/retrieval metadata
- orbit epoch range and per-satellite epoch records

### Observer and visibility

- validated observer-site model
- UTC ISO-8601 parsing
- offline Skyfield timescale
- SGP4 propagation
- topocentric elevation, azimuth, and slant range
- configurable sample interval and elevation threshold
- visible-only or all-satellite output
- element epoch distance
- configurable stale-element flag
- propagation error capture
- visibility metadata sidecar

### Event integration

- relative event time to absolute UTC conversion
- candidate sets before/during/after each event
- per-window maximum elevation
- candidate-set transition flag
- minimum element-epoch distance
- separate annotation sidecar preserving Event Profile v1 compatibility
- explicit non-identification semantics

### CLI

```text
leo-replay orbit import
leo-replay orbit visibility
leo-replay orbit annotate-events
```

### Schemas

- `observer-site-v1.schema.json`
- `orbit-source-v1.schema.json`
- `visibility-profile-v1.schema.json`
- `event-orbit-annotation-v1.schema.json`

### Offline fixtures

- OMM JSON
- OMM CSV
- TLE
- observer-site JSON

## Intentionally excluded

- automated online download
- historical archive retrieval
- connected-satellite identification
- handover classification
- 2D/3D visualization
- gateway and inter-satellite routing

These are separated to prevent orbit assumptions from being confused with measured communication behavior.

## Acceptance criteria

1. OMM JSON, OMM CSV, and TLE fixtures load offline.
2. All formats produce the same satellite identity and near-identical epoch.
3. A visibility CSV and metadata JSON can be generated without network access.
4. Every visibility row records orbit epoch distance and stale status.
5. Event annotations preserve the original event profile and use a sidecar.
6. Empty visible-candidate output remains valid and annotates as empty sets.
7. Existing v0.1-v0.3 replay tests continue to pass.
8. Repository checks and shell syntax tests pass.
