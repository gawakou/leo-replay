# v0.4.2 implementation

## Release objective

v0.4.2 adds reproducible historical element selection between the immutable acquisition layer introduced in v0.4.1 and the future synchronized map/timeline layer.

## Added modules

- `src/leo_replay/orbit/selection.py`
  - OMM JSON/CSV history loading
  - verified snapshot-directory input
  - causal selection by `CREATION_DATE`
  - retrospective selection by `EPOCH` distance
  - SGP4 position comparison at observation time
  - WGS84 sub-satellite coordinates
  - bracketing-element sensitivity
  - deterministic record fingerprints and compact audit output
  - optional complete OMM-field embedding for portable small selections

## CLI

```text
leo-replay orbit select-elements
```

The command supports a repeatable `--time` or a generated `--start` / `--duration-sec` / `--step-sec` range, satellite selectors, availability lag, stale thresholds, missing-creation-date policy, and comparison warning thresholds.

## Data contract

- `schemas/historical-element-selection-v1.schema.json`
- `examples/orbit/iss-history.example.json`

The output embeds selected OMM fields and references its source file or verified snapshot by SHA-256.

## Selection behavior

- Causal: latest record satisfying `CREATION_DATE <= observation_time - availability_lag`.
- Retrospective: record minimizing absolute epoch distance.
- Compare: both selections plus propagated-position difference.
- Missing creation dates are never silently interpreted as available.

## Validation target

- all v0.4.1 tests remain green;
- causal and retrospective policies choose different expected fixture records;
- availability lag changes causal eligibility deterministically;
- verified snapshot directories are accepted;
- missing `CREATION_DATE` is explicitly excluded or rejected;
- CLI output retains record fingerprints and map-ready subpoints;
- Docker bidirectional regression tests remain unchanged.

## Deferred work

- automatic widening/retry of empty `GP_History` queries;
- statistical uncertainty or covariance modeling;
- event-by-event visibility computed directly from selected historical elements;
- synchronized 2D map and timeline;
- active ping/traceroute measurement and station selection.
