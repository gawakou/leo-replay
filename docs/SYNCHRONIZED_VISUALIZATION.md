# Synchronized Orbit Map and Communication Timeline

v0.4.3 adds an offline visualization layer that combines historical element selection with communication conditions and optional visibility/event inputs.

## Research semantics

The map deliberately separates two reconstructions:

- **Causal**: the element available by the observation-time knowledge cutoff.
- **Retrospective**: the element whose epoch is closest to the observation time.

The satellite markers are geometric reconstructions. They do not identify the satellite that actually served a user terminal. A line between the two markers shows element-selection sensitivity, not a statistical confidence interval.

## Build a bundle

First generate a historical selection with multiple observation times:

```bash
leo-replay orbit select-elements \
  --input examples/orbit/iss-history.example.json \
  --mode compare \
  --start 2024-05-06T19:53:00Z \
  --duration-sec 150 \
  --step-sec 30 \
  --output /tmp/iss-selection.json
```

Then build the visualization:

```bash
leo-replay viz build \
  --selection /tmp/iss-selection.json \
  --site examples/orbit/observer-hiroshima.example.json \
  --profile examples/visualization/communication.example.csv \
  --events examples/visualization/events.example.json \
  --profile-start-utc 2024-05-06T19:53:00Z \
  --title "ISS causal and retrospective reconstruction" \
  --output-dir /tmp/leo-viz
```

The output directory contains:

```text
index.html       self-contained interactive view
 data.json       normalized machine-readable bundle
 manifest.json   hashes and build summary
 README.txt      opening instructions
```

`index.html` can be opened directly without a network connection. It embeds a simplified world outline, data, CSS, and JavaScript and makes no external requests.

## Local server

```bash
leo-replay viz serve \
  --input-dir /tmp/leo-viz \
  --open-browser
```

The default bind address is `127.0.0.1`. A non-loopback address is rejected unless `--allow-remote` is given because this development server has no authentication or TLS.

## Optional visibility input

A visibility CSV generated by `leo-replay orbit visibility` may be attached:

```bash
leo-replay viz build \
  --selection /tmp/selection.json \
  --site site.json \
  --visibility /tmp/visibility.csv \
  --output-dir /tmp/leo-viz
```

Visibility samples are joined by observation time and NORAD catalog ID within `--visibility-tolerance-sec` (default 0.75 s). The viewer can then filter to visible candidates and display elevation and range.

## Communication profile input

The profile CSV accepts either an absolute `timestamp_utc` column or a relative time column named `sec`, `elapsed_sec`, or `time_sec`. Supported metrics are:

- `rtt_ms` or `ping_rtt_ms`
- `delay_ms`
- `jitter_ms`
- `loss_pct`
- `rate_mbit`, `rate_mbps`, or `throughput_mbps`
- `note` or `state`

Relative profiles use the first selection time unless `--profile-start-utc` is specified.

## Scalability boundary

The bundle is an analysis and presentation view, not a high-volume orbital database. `--maximum-satellites` defaults to 20,000 and prevents accidental generation of an unbounded browser payload. For large constellations, reduce the selection to the observation region or event window before building the bundle.

## Offline map data

The embedded land outline is derived from simplified Natural Earth low-resolution public-domain geometry. No map-tile service is contacted.
