# v0.3.0 implementation

## Objective

v0.2.0で統合した時系列・イベント再現を、forward/reverse独立制御へ拡張する。論文で明示した片方向root netemの制約を解消し、RTTが往復値であること、ACK経路がプロトコル性能へ影響することを評価可能にする。

## Added modules

- `directional_profile.py`
  - 双方向CSVの読込み・出力
  - legacy profileの分解規則
  - Event Profile v1の方向別拡張
- `tc_backend.py`
  - netemコマンド生成
  - root qdisc操作
  - IFB準備・後処理
- `bidirectional_replay.py`
  - dual-egress/IFBターゲット管理
  - 時系列・イベントの双方向スケジューリング
  - 方向別実行ログ

## Compatibility

- `--direction-mode single`はv0.2.0のスクリプトを呼び出す。
- 従来CSVは再生時に自動的に方向別条件へ変換できる。
- Event Profile v1の`parameters`は維持し、任意の`directions`を追加した。
- schema versionは後方互換な拡張として`1.0`を維持した。

## Acceptance tests

- legacy RTTの50:50分割
- end-to-end損失確率を保存する分解
- up/down別名列の読込み
- directional CSV生成
- Event Profile v1方向拡張と検証
- dual-egress dry-run
- IFB ingress redirect dry-run
- 方向別execution log
- v0.1/v0.2回帰テスト

## Linux validation remaining

CIではroot権限による実ネットワーク制御を実施しない。検証ルータで次を確認する必要がある。

1. 2 NICのforward/reverse対応
2. IFB redirectの実動作
3. ping RTTに対する方向別遅延の合成
4. 上下方向のiperf3帯域制御
5. 50～500 msイベントにおける方向別適用遅延
6. Ctrl-Cおよび異常終了後のqdisc残存状態
