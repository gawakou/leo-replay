# v0.4.1 implementation

## Objective

Freeze provider responses as verifiable orbit snapshots before historical-element selection and map visualization are added.

## Added modules

- `orbit/acquisition.py`: CelesTrak and Space-Track clients, request builders, authentication, batching, and provider policy checks.
- `orbit/snapshot.py`: atomic snapshot writing, raw-part preservation, OMM/TLE validation, merging, hashes, and verification.

## Public CLI

- `leo-replay orbit fetch celestrak`
- `leo-replay orbit fetch space-track`
- `leo-replay orbit verify-snapshot`

## Design decisions

1. OMM-compatible JSON/CSV is the preferred acquisition format; TLE remains available for compatibility.
2. Space-Track credentials are read from environment variables and never serialized.
3. CelesTrak responses are not automatically retried, and the two-hour update interval is enforced for replacement of an existing matching snapshot.
4. Space-Track ID lists are batched to avoid excessively long or broad requests.
5. Raw response parts and merged data are both retained.
6. Existing matching snapshot directories are reused without network access.
7. Historical acquisition and historical-element selection remain separate operations.

## Deferred to v0.4.2+

- Causal selection using information available at the observation time.
- Retrospective nearest-epoch selection.
- Element disagreement and uncertainty metrics.
- Synchronized 2D map, sky view, timeline, and later 3D globe visualization.
